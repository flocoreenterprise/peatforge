# Core demo acceptance — one server, one tunnel

Use only this fresh implementation. No rehearsal source or reference application browsing.
The operator is openly accessible by user instruction. All field delivery is mocked until explicitly configured and tested.

## Before opening the integrated tunnel

1. Run engine and backend tests, build web. All must pass; record commands and counts.
2. Verify `/api/config` identifies public operator access separately from actual environmental provider/model/cache provenance.
3. Verify real cached2019 weather is used by replay; missing data never becomes an unlabeled fixture or fake zero.
4. Security reviews routes, demo storage isolation, mock outbound, webhook authentication, error/log redaction.
5. Serve web/dist and `/api` from FastAPI8000. Tunnel only that port. Access logs disabled.

## Manual browser acceptance

1. Open cloud URL at1440,1024,390. Operator should open without asking PIN. Check no clipped controls, readable labels, visible provenance.
2. Inspect pilot village metadata, risk layer and detail. Water table always labelled a model estimate; hotspot count is detection count.
3. Select Replay2019 and a day with useful baseline crossing; compare baseline/intervention curves and inspect assumptions.
   Do not demand a predetermined Days Bought number. Exact, zero, null and lower-bound states must render honestly.
4. Trigger a mock alert for a registered demo responder in the selected village/context.
5. Enter `AIR 61 ASAP YA dekat kanal 4` through the demo responder/message control.
   A readback must appear. The embedded `ASAP YA` must NOT confirm the full report.
6. Enter standalone `YA`. Check the confirmed observation and proposal use the same replay context and deterministic tool result.
   If discrepancy needs verification, it must create a visible verification item, never disappear.
7. Approve a proposed action. It becomes approved (not executed), and one follow-up is visible for the same responder.
   Repeated approval must not send another follow-up. Reject a separate proposal and verify rejection is persisted.
8. Refresh and wait for polling: Command4s, any responder control3s. Check state persists and is consistent across panels.
9. Check transcript for unsupported promises: never claim actual execution, guaranteed safety or validated days of fire prevention.

Capture screenshots after visible outcomes. Reset temporary viewport override when finished.
Record actual failures, fixes and rechecks. Provider setup and real delivery are separate UAT, not implied by a mock pass.
